# Deploy AI Mystery Room on Render

This project can run as one Render web service: Express serves both the built React app and the API. The browser and API therefore share one HTTPS origin, so the signed session cookie works without separate frontend CORS configuration.

## 1. Prepare the repository

1. Create an empty private or public GitHub repository.
2. From this project folder, run the following commands (replace the URL with your repository URL):

   ```powershell
   git init -b main
   git add .
   git status --short
   git commit -m "Prepare AI Mystery Room for deployment"
   git remote add origin https://github.com/YOUR-NAME/YOUR-REPOSITORY.git
   git push -u origin main
   ```

3. Before committing, confirm `.env` is ignored and is not listed by `git status`. Keep Gemini keys, MongoDB credentials, and session secrets out of GitHub.
4. Keep `render.yaml` at the repository root. Render uses it to set the build, start, health check, and required secret variables.

## 2. Create the MongoDB Atlas database

1. In MongoDB Atlas, create a project and a cluster. An Atlas Free cluster is suitable for a small demo; choose a region near the Render service where available.
2. Create a database user with a strong password. This is separate from your Atlas website login.
3. In **Network Access**, allow the Render service's outbound IP ranges. After creating the Render service in step 4, find them in its **Connect → Outbound** panel and add those CIDR ranges to Atlas. Avoid `0.0.0.0/0`; it allows connections from anywhere.
4. In Atlas, select **Connect → Drivers** and copy the `mongodb+srv://` connection string. Replace its username, password, and database name as needed. URL-encode special characters in the password.

Atlas only accepts connections from its project IP access list, and Render documents the outbound CIDR ranges for each service. Add the service's ranges rather than opening the database globally. See [Atlas IP access lists](https://www.mongodb.com/docs/atlas/security/ip-access-list/) and [Render outbound IP addresses](https://render.com/docs/outbound-ip-addresses).

## 3. Create the Render Blueprint

1. In Render, choose **New → Blueprint** and connect the GitHub repository.
2. Select the branch containing `render.yaml` and create the Blueprint.
3. When Render prompts for `MONGODB_URI` and `GEMINI_API_KEY`, enter their values in the dashboard prompt. The blueprint generates `SESSION_SECRET` for you and sets `GEMINI_MODEL` to `gemini-3.8-flash`.
4. The first deployment may fail its startup health check until Atlas allows the Render outbound ranges. Complete step 2.3, then redeploy the service from Render.

Render runs `npm ci --include=dev && npm run build`, starts the service with `npm start`, and checks `/api/v1/health`. The service binds to Render's `PORT` on `0.0.0.0`.

## 4. Verify the live deployment

1. Open the service's `https://…onrender.com` URL. The app and `/api/v1/health` should load from that same host.
2. Check `/api/v1/health` returns JSON with `status: "ok"` and `database: "connected"`.
3. Create a fictional case, refresh the page, open case files, and confirm the case is still associated with the same browser.
4. If you add a custom domain, set `CLIENT_URL` in Render to the exact origin (for example, `https://mystery.example.com`) and redeploy. Do not include a path.

## Required Render settings

The Blueprint supplies these settings:

| Variable | Value |
| --- | --- |
| `NODE_ENV` | `production` |
| `SESSION_SECRET` | Generated by Render |
| `MONGODB_URI` | Atlas connection string, entered as a secret |
| `GEMINI_API_KEY` | Google AI Studio key, entered as a secret |
| `GEMINI_MODEL` | `gemini-3.8-flash` |
| `CLIENT_URL` | Optional for the default Render URL; set to the exact origin when using a custom domain |

Do not set `VITE_API_URL` for this single-service deployment; the frontend uses the same-origin `/api/v1` path. A Render Free web service sleeps after 15 minutes without traffic and can take about a minute to wake. Choose a paid instance if you need it to stay available without cold starts. See [Render's free instance limits](https://render.com/docs/free).

## Local development

Copy `.env.example` to `.env`, add your local credentials, run `npm install`, then `npm run dev`. The Vite development server proxies `/api` requests to Express on port 5000.
